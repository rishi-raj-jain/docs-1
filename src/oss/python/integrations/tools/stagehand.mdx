[Stagehand v4](https://docs.stagehand.dev/v4/first-steps/introduction) is an open-source SDK for browser automation. Its [Deep Agents integration](https://docs.stagehand.dev/v4/integrations/agent-frameworks/deep-agents) exposes a persistent browser through an MCP server, with local Chrome or [Browserbase](/oss/integrations/providers/browserbase) as the browser.

See [Browser use](/oss/deepagents/browser-use) for the main guide. Use the setup below to run Stagehand's existing agent examples without defining custom browser tools.

<Note>
  This experimental integration requires Stagehand v4. Stagehand ships it from its repository, not as a standalone adapter package.
</Note>

## Tools

| Tool | Description |
|------|-------------|
| `run` | Execute JavaScript or snapshot actions against the active browser page |
| `snapshot` | Inspect the active page and hydrate bracketed element IDs for use in `run` |
| `screenshot` | Capture a screenshot of the rendered page |

## Setup

### Prerequisites

- Python 3.11–3.13.
- [uv](https://docs.astral.sh/uv/).
- A model-provider API key for the deep agent, such as `OPENAI_API_KEY`.
- Current Google Chrome for local mode, or a Browserbase API key for a remote browser.

### Clone and install

Run these commands in the environment that runs the agent:

```bash
git clone https://github.com/browserbase/stagehand.git
cd stagehand/packages/integrations/deepagents
uv sync --locked
uv sync --project examples/local --locked
```

The server and agent use separate Python environments. The stdio transport isolates Stagehand's and the LangGraph SDK's incompatible `websockets` requirements.

### Configure the agent

Open [`examples/local/agent.py`](https://github.com/browserbase/stagehand/blob/main/packages/integrations/deepagents/examples/local/agent.py) and set `model` to a model available to your provider account. Edit `instruction` and the optional Pydantic `response_format` for your task. Export the matching model-provider credential, for example:

```bash
export OPENAI_API_KEY="your-openai-api-key"
```

The agent's model credential is separate from optional credentials for Stagehand AI methods called inside `run`. See [Server configuration](#server-configuration).

### Choose the browser

Both modes use the same agent example and tools. Run one of these configurations from `packages/integrations/deepagents`:

<CodeGroup>
```bash Local Chrome
export STAGEHAND_BROWSER="local"
export STAGEHAND_HEADLESS="true"
uv run --project examples/local --locked python examples/local/agent.py
```

```bash Browserbase
export STAGEHAND_BROWSER="browserbase"
export BROWSERBASE_API_KEY="your-browserbase-api-key"
uv run --project examples/local --locked python examples/local/agent.py
```
</CodeGroup>

Local mode launches visible Chrome by default. The local example above explicitly enables headless mode for environments without a display, such as sandboxes. Chrome must be installed in that environment.

<Note>
  A local browser runs alongside the MCP server. In a sandbox, `localhost` refers to that sandbox, not your laptop. A Browserbase browser runs remotely and cannot reach a sandbox's `localhost`; use a URL reachable from the remote browser instead. `STAGEHAND_HEADLESS` applies only to local Chrome.
</Note>

## Use with a deep agent

The upstream example uses `create_deep_agent` with tools loaded through `langchain-mcp-adapters`. Its [`_client.py`](https://github.com/browserbase/stagehand/blob/main/packages/integrations/deepagents/examples/local/_client.py) starts `stagehand-deepagents-mcp` over stdio and forwards only `STAGEHAND_*` and `BROWSERBASE_*` environment variables to the server.

<Warning>
  Keep the example's persistent `client.session(...)` context open for the entire agent run. Stateless tool loading starts a new stdio process for each call and loses the browser and snapshot IDs. Take a new snapshot after navigation or when IDs become stale.
</Warning>

For a structured-output form-filling example with mock data, use [`agents2.py`](https://github.com/browserbase/stagehand/blob/main/packages/integrations/deepagents/examples/local/agents2.py). Set its `model` to a model available to your account before running it. Its instructions ask the agent to fill the form without submitting it:

```bash
uv run --project examples/local --locked python examples/local/agents2.py
```

The `run` tool executes model-authored JavaScript in the browser. Use Browserbase for untrusted tasks and review Stagehand's [integration security boundary](https://docs.stagehand.dev/v4/integrations/agent-frameworks/overview#security-boundary).

## Server configuration

| Variable | Default | Purpose |
|----------|---------|---------|
| `STAGEHAND_BROWSER` | `local` | Select `local` or `browserbase` |
| `STAGEHAND_HEADLESS` | `false` | Run local Chrome headlessly |
| `STAGEHAND_START_URL` | Unset | URL to open when the server starts |
| `STAGEHAND_MODEL` | Unset | Optional model for Stagehand AI methods called inside `run` |
| `STAGEHAND_MODEL_API_KEY` | Unset | Required with `STAGEHAND_MODEL`; the server does not receive the agent's model-provider credential |
| `STAGEHAND_API_URL` | Unset | Optional Stagehand Model Gateway URL |
| `STAGEHAND_RUN_TIMEOUT_MS` | `60000` | Timeout for JavaScript and snapshot-action batches |
| `BROWSERBASE_API_KEY` | Unset | Required for Browserbase |
